# CISC: Confidence Improves Self-Consistency in LLMs

> This note records a reading of the original paper and the official implementation; for the adaptation and settings currently used in this repo, see the [experimental protocol](../protocol.md).
- Paper: Findings of ACL 2025, pp. 20090–20111, https://aclanthology.org/2025.findings-acl.1030/ / arXiv:2502.06233 (v1 2025-02-10, v2 2025-09-29); Amir Taubenfeld*, Tom Sheffer*, Eran Ofek, Amir Feder, Ariel Goldstein, Zorik Gekhman, Gal Yona (Google Research / Hebrew University / Columbia)
- Official code: https://github.com/taubenfeld/CISC (the README states it is the official implementation of ACL Findings 2025; Apache-2.0; Python, with `src/`, `setup.py`, a demo notebook; checked 2026-10-07. Note: an earlier search misjudged it as "no code" because of GitHub API rate limiting; corrected.)
- Category: multi-sample semantic consistency + single-trace verbalized/P(True) ("confidence-weighted self-consistency voting": a self-assessed confidence is taken on each CoT, followed by within-question softmax-weighted majority voting)
- Access requirements: gray-box (P(True) and Response Probability need token logprobs; the Verbal variants work in black-box); no training, only a temperature T fitted on a 10% labeled held-out set (labels = ground-truth answers); no extra model (the same model self-assesses).

## 1. Method design
**CISC (Confidence-Informed Self-Consistency, §3)**: given a question q and m responses {(r_i, a_i)} (r = reasoning chain, a = final answer):
1. Confidence extraction: for each (r_i,a_i), obtain a self-assessed score c_i∈R.
2. Normalization (within-question softmax): c̃_i = exp(c_i/T) / Σ_{j=1..m} exp(c_j/T), where T is a tunable temperature (T→∞ reduces to plain SC; T→0 selects only the single highest-confidence response).
3. Aggregation: â_CISC = argmax_a Σ_{i=1..m} 1[a_i = a] · c̃_i.
CISC itself is a "decoding/aggregation" strategy, and **the paper does not evaluate it as a UQ scorer with AUROC/PRR**; what is useful for this project is its confidence-extraction methods and the WQD metric.

**Four confidence-extraction methods (§4.1, Appendix B Table 5)**:
- **Response Probability** (from Wang et al. 2022): length-normalized sequence probability p_θ(r,a) = [Π_{i=1..n} p_θ(x_i | x_<i, q)]^{1/n}.
- **Verbal Binary**: after the response, append "Now I will rate my confidence in the proposed answer as either 0 or 1. Proposed confidence: (", and have the model output 0/1.
- **Verbal 0-100**: append "Now I will rate my confidence in the proposed answer on a scale of 0-100. Proposed confidence: (".
- **P(True)** (adapted from Kadavath et al. 2022, **works best**): uses the same prompt as Verbal Binary and reads the probability the model assigns to the token "1" as c_i (the original changes True/False to 0/1 to avoid confusion with the datasets' True/False labels; whether it is renormalized over {0,1}: not stated in the paper). "(0" and "(1" are two separate tokens in all evaluated models.
- **Two-step prompting**: first generate (r,a), then append the confidence prompt e after (q,r,a) and continue generation; the prefix is therefore unchanged and the KV cache can be reused, with extra cost only for encoding about 20 tokens and generating 1 token ("<5% of the input + reasoning-chain length", §10).

**Temperature T (§4.5, Appendix D)**: for each (model, confidence method), T is chosen by grid search on a 10% held-out set (merged across the four datasets) (80 evenly spaced values, range 10^-4 to 10^4, a few minutes, no need to rerun the LLM); P(True) confidences are very close to each other and need a smaller temperature (§5). A softmax without temperature (T=1) hurts performance (Table 8).

**WQD (Within-Question Discrimination, Def. 6.1)**: for each question, take its set of correct responses R_q^+ and incorrect responses R_q^-; WQD = the fraction of (correct, incorrect) response pairs (within the same question) in which the correct response has higher confidence (the formula is missing from the md; per the main text: statistics over the (correct, incorrect) pairs of all questions; tie handling is not stated). It measures how well confidence separates correct from incorrect within a question, unaffected by between-question difficulty.

**Key experimental setup (merged here because this note only has §1/§6)**:
- Datasets (§4.2): GSM8K validation set, 1320 questions; MATH test set, 5K; MMLU-Pro, random 5K; Big-Bench-Hard, 20 of 23 subtasks, 5,761 questions in total. 30 samples per question (§4.6), about 500K responses and 17,000 questions per model (Appendix F); Gemma2-2B takes about 100 H100 GPU hours.
- Models (§4.3): 9 open-source instruct models: Gemma2 {2B,9B,27B}, Qwen2.5 {3B,14B,72B}, Ministral-8B-Instruct-2410 / Mistral-Small-Instruct-2409 (22B) / Mistral-Large-Instruct-2411 (123B).
- Prompt (Appendix B Table 4): zero-shot; "Before giving your answer, provide a step-by-step explanation of your thought process. Then on a new line, give your proposed answer adhering to this precise format: 'Proposed answer: (X).'"; MATH requires the answer as a TeX expression.
- Sampling temperature/top-p/max_tokens: not reported (not found in the main text or appendix).
- Evaluation: bootstrap - first sample 30 responses, then for each budget b∈[1,30] draw 500 sets of b paths and average the accuracy (§4.6); metrics are % Cost Reduction (fix the CISC budget at 5 or 10 and find how many samples SC needs to reach the same accuracy, counted as 31 if over 30) and % Accuracy Improvement; confidence intervals use 10,000 bootstrap resamples (Appendix C, n≈150,000 rows).
- Main results (Table 1, macro average): P(True) Cost Reduction 41% (SC needs 8.4 samples to match CISC at 5) / 46% (18.6 samples to match 10), Acc improvement 1.6% / 1.1%; Response Probability 22%/31% (1.1%/0.8%); Verbal 0-100 22%/30% (0.8%/0.4%); Verbal Binary 18%/10% (0.4%/0.2%). Table 2: P(True) unnormalized 32% → normalized 46%. Table 3: ECE-t / Brier-t / WQD / Cost Reduction - Verbal Binary 0.005/0.187/52.2%/10%; Verbal 0-100 0.046/0.173/56.1%/30%; Response Prob. 0.090/0.192/59.0%/31%; P(True) 0.030/0.182/62.3%/46% (the best-calibrated method is the least helpful for CISC; WQD accurately predicts the CISC ranking). Table 10: P(True) WQD is all >50%, ranging 53.5%–81.4% (e.g. Mistral 22B GSM8K 81.4%, Qwen-3b MMLU 56.0%). Table 9: taking "only the highest confidence" (Max) actually decreases accuracy (Acc −1.9%/−4.5%); using confidence only for tie-breaking (Tie) gives 27%/28%.
- Human analysis (§7, MMLU-Pro, 90 samples): among responses the model judged to have relatively low confidence, 67% were human-labeled as showing signs of low-quality reasoning, versus only 33% among high-confidence ones.

## 6. Fit to this project's unified benchmark
- **Relation to SC**: CISC adds confidence weights on top of SC; the "majority vote share" in SC.md is its T→∞ limit. If a "response-level correctness score" is needed, there are two natural definitions (both are extensions by this project; the original does not evaluate AUROC): (a) the c_i of a single response (the P(True) token probability); (b) the weighted vote share of the selected answer, Σ_{i: a_i=a} c̃_i (summed after clustering math answers by equivalence with math_verify). The report must state that this is a proxy.
- **Long-CoT math + vLLM**: the P(True) prompt can be appended directly after the full output (including `</think>` and the final answer), using the completion (non-chat) interface with prefix-cache reuse; only the logprob of "1"/"0" at the next token needs to be read, and vLLM top-k (≥5, 20 recommended) logprobs suffice ("1" outside the top-k is treated as ≈0 and the fraction is recorded). It must be verified whether "(1" is split into "(" + "1" under the Qwen3 tokenizer as well (the paper only confirms its 9 models). Note that a thinking model may continue with a new `<think>` after the appended text; the suggestion is to use raw completion and take only the first-step logprobs, or to place the appended content outside the already-closed thinking; this is a pitfall that needs a pilot experiment to confirm.
- **Response Probability variant**: the length-normalized geometric-mean probability is nearly saturated and similar across samples on CoTs of thousands of tokens, so the softmax temperature must be very small; also, vLLM only gives top-k logprobs, but the logprob of the sampled token itself is available, so this variant can still be implemented (equivalent to the exponential of Perplexity).
- **Temperature T needs a labeled held-out set**: the paper fits it on 10% of the data per model; in the benchmark it must be fitted on the val split and evaluated on test, to avoid leakage; for ranking metrics such as AUROC/PRR, T is only meaningful within a question, and the overall ranking is insensitive to T (except for monotone transformations, which change after weighted summation).
- **Extra cost per question**: nearly zero - reuse the m full generations of SC, then for each add a ~20-token forward pass and 1-token generation (m very short decodes in total); no extra model.
- **Recommended faithful setting**: m=30 (at least 5/10 for budget curves), P(True) with the 0/1 prompt and within-question softmax(c/T), with T fitted on the held-out set over an 80-point grid [1e-4,1e4]; evaluation reports WQD (since it is predictive of CISC) together with the SC control. Limitation: the paper only tests short-CoT instruct models (Gemma2/Qwen2.5/Mistral) and does not cover the long thinking of reasoning models; the WQD of P(True) in that setting must be verified by ourselves.
