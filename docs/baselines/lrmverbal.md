- Official code: https://github.com/MattYoon/reasoning-models-confidence (README is tagged "[NeurIPS 2025]"; no LICENSE file in the repository root, GitHub API license=None; contains forked evalchemy and lm-evaluation-harness (the latter ships its own LICENSE.md); framework: Python + evalchemy/lm-eval-harness + vLLM (scripts set `VLLM_USE_V1=0`, an older vLLM) + OpenAI API as judge; last push 2025-11-19). Availability: the main experiments (Sec. 3), slope (Sec. 4.1), ablations (Sec. 4.2), and ICL slow thinking (Sec. 4.3) all have shell scripts; the datasets are uploaded to HF (`DKYoon/triviaqa_val_1k`, etc.); metric computation is in `results/calculate_metrics.ipynb` (paths hard-coded). - Category: single-trace verbalized (the paper is essentially an empirical study of verbalized confidence rather than a proposal of a new scorer; it can serve as the "long-CoT reasoning model + 10-bin verbal/numeric confidence" baseline)
- Access requirements: black-box (only generated text is needed; no logprobs); no training; the evaluated model itself needs no extra model, but correctness labeling uses a GPT-4o-mini judge (code `gpt-4o-mini-2024-07-18`, temperature 0), and the ablation CoT rewriting uses GPT-4.1.

## 1. Method design
**Core claim**: reasoning models (long CoT / slow thinking) are better calibrated in verbalized confidence; the gain comes from "non-linear reasoning" in slow thinking, such as exploring alternatives and backtracking, rather than from explicit confidence reasoning (Sec. 4.2).

**Single-turn three-step reasoning (Sec. 3.1, App. B.2 Listing 1)**: in the same conversation turn the model is asked to (1) SOLUTION REASONING; (2) CONFIDENCE REASONING (assess its own confidence step by step); (3) CONFIDENCE VERBALIZATION, mapping the confidence to one of 10 bins. Reasoning models are expected to complete all three steps inside `<think>...</think>`.

**Prompt (verbatim from the paper's Listing 1, placed before the question; in the code it is `PROMPT + question`)**:
```
First, reason through the question step by step to arrive at an answer. Then, thoroughly assess your confidence in that answer by evaluating your thinking process so far. Finally, classify your confidence into one of the following classes based on how likely your answer is to be correct:
- "Almost no chance" (0.0–0.1) - "Highly unlikely" (0.1–0.2) - "Chances are slight" (0.2–0.3) - "Unlikely" (0.3–0.4) - "Less than even" (0.4–0.5) - "Better than even" (0.5–0.6) - "Likely" (0.6–0.7) - "Very good chance" (0.7–0.8) - "Highly likely" (0.8–0.9) - "Almost certain" (0.9–1.0)
Each category reflects the probability that your answer is correct.
At the very end of your output, format your answer and confidence as **Answer**: $ANSWER **Confidence**: $CLASS where CLASS is one of the names (only the names without the probability ranges) of the classes above.
```
Note the differences between code and paper: in the reasoning-model tasks (`reasoning_no_force` / `reasoning_force`) the final sentence of the prompt is changed to "Format your answer and confidence as … The ANSWER should be short and concise. Output only the answer and confidence and nothing else."; the non-reasoning task (`non_reasoning`) keeps the "At the very end of your output…" version. QwQ (and Skywork OR1, first turn only) additionally gets a system prompt: "Make sure to include both of the thinking process for the question and the confidence assessment in the <think> tags."

**Forced CONFIDENCE REASONING (Sec. 3.1)**: R1-Distill, OR1-Preview, and GLM-Z1 rarely do confidence reasoning inside think, so generation is stopped at `</think>`, which is replaced with "Okay, now let's assess my overall thinking process so far step-by-step. I need to evaluate how likely my answer is correct." (the code adds ", and express my confidence using the provided class names."), followed by a second round of reasoning (max_new_tokens=2048 for the second round in the code). Sec. 4.2 shows that this operation has little effect on calibration. QwQ, EXAONE-Deep, and Qwen3 Thinking are not forced (README).

**Answer/confidence extraction (Sec. 3.1, App. B.2 + code)**:
- Paper description: extract with a regex; on format failure ("rare"), reason once more: non-reasoning models are asked to re-output only the answer and confidence; for reasoning models, generation up to `</think>` is followed by replacing it with `</think>Answer:` and reasoning again.
- What the code actually does: reasoning models **always** use `</think>` as the stop, then append `\n</think>\n\n**Answer**:` and greedily generate <=64 tokens to obtain the answer + confidence (regardless of whether the first round already gave a formatted output, and regardless of truncation by max tokens); non-reasoning models **always** get a second user turn: "Repeat your answer and confidence in the requested format … If the question was multiple choice, just output the correct option. If you didn't find an answer yet, give me your best guess. You must give an answer and its confidence." (<=512 tokens).
- Regex `extract_confidence_10_bin`: `Confidence[\s\*]*:?\s*[\*]*\s*(Almost no chance|Highly unlikely|…|Almost certain)` (case-insensitive); on failure it takes the text after `**Confidence**: `.

**Scoring**: bin names are mapped to the interval midpoints (`results/calculate_metrics.ipynb`): almost no chance 0.05, highly unlikely 0.15, chances are slight 0.25, unlikely 0.35, less than even 0.45, better than even 0.55, likely 0.65, very good chance 0.75, highly likely 0.85, almost certain 0.95. The output takes 10 discrete values {0.05,…,0.95}, semantically "the probability that the answer is correct" (Sec. 2: confidence = estimated probability that answer is correct). The scored object is the model's own final answer (response-level).

**Variants (App. A.2)**: Two-turn (first turn solves, second turn does confidence reasoning + expression), Top-K (K=4 candidate answers each with a confidence, take the highest), Multi-step (K=4 steps, each giving a confidence, take the final confidence), language-only description (no probability ranges), direct numeric probability (no binning).

## 2. Dataset setup
All datasets are uniformly sampled to **1,000** items (Sec. 3.1); in the authors' HF datasets they are all stored as the `validation` split, and the source split of the original datasets is not reported in the paper (the HF names for TriviaQA/NonambigQA are `*_val_1k`).
- **TriviaQA** (knowledge-focused, open-domain short-answer QA): `DKYoon/triviaqa_val_1k`, fields question + answers (multiple aliases).
- **NonambigQA** (knowledge-focused; the subset of unambiguous questions from NQ/AmbigQA): `DKYoon/nonambigqa_val_1k`.
- **MMLU-Pro Math / Non-Math** (reasoning-intensive, multiple choice): the paper says the Math subset is "focused on arithmetic reasoning"; the HF names are `mmlupro_calc_val_1k` / `mmlupro_non_calc_val_1k`, with question format "Topic: <subject>.\nQuestion: …\nA) …"; the "calc" subset is visibly cross-disciplinary (e.g. business calculation problems) and not pure math-competition problems; the exact selection rule is not reported.
- **SuperGPQA Math / Non-Math** (reasoning-intensive, multiple choice): the HF names are `supergpqa_calc_middle_val_1k` / `supergpqa_non_calc_middle_val_1k` (inferred from the names to be a "requires calculation + middle difficulty" subset; the paper does not report the selection rule).
- **Answer format**: QA answers are short text; for multiple choice, gold `answers` = [letter, option text, "letter) option text"].
- **Correctness labeling**: GPT-4o mini + the OpenAI `simple-evals` (SimpleQA grader) prompt, outputting CORRECT/INCORRECT/NOT_ATTEMPTED (A/B/C in the code); multiple golds are joined with ", or " and annotated with "(Any of these answers are acceptable.)"; NOT_ATTEMPTED is counted as incorrect (correct=0).
- Sec. 4.1/4.2 use only TriviaQA and NonambigQA (accuracy is more stable when the CoT is truncated).

## 3. Experimental protocol
- **Number of generations**: the main experiments use 1 per question (greedy). Reasoning models = first-turn thinking (+ second-turn confidence reasoning for forced models) + one answer/confidence completion of <=64 tokens; non-reasoning models = one turn + one repeat turn.
- **Decoding**: greedy (temperature 0, `do_sample=False`); max tokens: 4096 for knowledge datasets, 8192 for reasoning datasets (App. B.2); vLLM `max_model_len` 8192 / 12288, bf16, tensor_parallel_size=2, `enforce_eager=True` (scripts). The seed parameter in the code is `[0,1234,1234,1234]`.
- **Sampling robustness (App. A.2.3, Table 9)**: R1-Distill-Qwen-32B with the recommended sampling temperature=0.6 (top-p not reported), 5 runs reporting mean ± standard deviation.
- **Bootstrap (App. A.2.4, Table 10)**: only Qwen2.5-32B-Inst and R1-Distill-Qwen-32B, 5 resampled subsets of 1,000.
- **Metrics**: ECE (10 equal-width bins, code `compute_ece(n_bins=10)`), Brier Score (sklearn `brier_score_loss`), AUROC (sklearn `roc_auc_score`, with confidence as the score for correctness); Accuracy for reference. **Samples whose confidence cannot be parsed are dropped from ECE/Brier/AUROC (`dropna`), but accuracy is still computed over all samples** (the notebook prints the "Faulty" count).
- **CoT progress analysis (Sec. 4.1)**: the CoT is cut by token count into 11 cumulative segments (0%,10%,…,100%), and `</think>\nAnswer:` is appended (reasoning models; `\nAnswer:` for non-reasoning models; `\n</think>\n\n**Answer**:` in the code) to terminate early and obtain the answer and confidence; for each metric a linear regression against progress is fit, reporting the slope and p<0.05 significance (Table 3).
- **Ablations (Sec. 4.2, App. B.3)**: on the original CoT of R1-Distill-Qwen-32B, remove Confidence Reasoning / Epistemic Markers / Non-linear Reasoning (the latter two rewritten by GPT-4.1 + 3-shot), then re-prompt; manual check of 100 examples: after truncating Confidence Reasoning only 4/100 still contain explicit confidence reasoning; removing epistemic markers 91/100 qualified; linearization 100/100 qualified. No CoT lower bound: directly `</think>`.
- **ICL slow thinking (Sec. 4.3)**: 3 slow-thinking examples from R1-Distill-Qwen-32B on held-out TriviaQA are used as few-shot.
- **Budget forcing (Sec. 5, Fig. 4 left)**: append "Wait," 0-4 times at the end of the CoT.
- **Compute (App. B.1)**: A6000 48GB or A100 80GB; 2 GPUs for 32B models; a 32B reasoning model takes about 1 hour per dataset (2×A6000).

## 4. LLM backbone setup
- Four 32B-class backbones, six reasoning models vs. non-reasoning counterparts (Sec. 3.1):
  - Qwen2.5-32B: R1-Distill-Qwen-32B, QwQ-32B, Skywork OR1-Preview (32B) vs. Qwen2.5-32B-Instruct;
  - GLM-4-32B-0414: GLM-Z1-0414 vs. GLM-4-0414;
  - EXAONE-3.5-32B: EXAONE-Deep (32B) vs. EXAONE-3.5-32B-Instruct (EXAONE uses `<thought>` tags);
  - Qwen3-32B: Thinking mode vs. Non-thinking mode (same checkpoint; non-thinking is done by injecting an empty `<think></think>`; the code uses `apply_chat_template(enable_thinking=True)`).
- Precision bf16, inference framework vLLM (App. B.1 + scripts); context `max_model_len` 8192/12288.
- The scale analysis (Sec. 5, Fig. 4 right) covers multiple sizes of R1-Distill, GLM-Z1, Qwen3 Thinking, and EXAONE-Deep (x-axis 0-30B); the main text does not list the specific sizes.

## 5. Main results and conclusions (brief, key numbers)
- **Overall**: 6 reasoning models × 6 datasets; in 33/36 settings the reasoning model is strictly better than its non-reasoning counterpart on all metrics (Abstract, Sec. 1).
- **Table 1 (TriviaQA, Acc/ECE/Brier/AUROC)**: Qwen2.5-Inst 0.718/0.129/0.176/0.769 vs. R1-Distill-Qwen 0.727/0.042/0.157/0.782, QwQ 0.768/0.063/0.137/0.807; GLM-4 0.814/0.084/0.137/0.675 vs. GLM-Z1 0.824/0.029/0.120/0.777; Qwen3 Non-thinking 0.711/0.207/0.230/0.650 vs. Qwen3 Thinking 0.768/0.063/0.137/0.807.
- **Math-related subsets (Table 11/12, Acc/ECE/Brier/AUROC)**:
  - MMLU-Pro Math: Qwen2.5-Inst 0.669/0.094/0.170/0.806; R1-Distill 0.785/0.105/0.121/0.842; QwQ 0.833/0.047/0.094/0.871; GLM-4 0.802/0.067/0.131/0.794 vs. GLM-Z1 0.861/0.072/0.095/0.783; EXAONE-3.5 0.598/0.156/0.243/0.676 vs. EXAONE-Deep 0.809/0.036/0.110/0.776; Qwen3 Non-thinking 0.787/0.083/0.155/0.708 vs. Thinking 0.833/0.047/0.094/0.871.
  - SuperGPQA Math: Qwen2.5-Inst 0.485/0.230/0.295/0.621; R1-Distill 0.592/0.115/0.218/0.677; GLM-4 0.609/0.208/0.256/0.681 vs. GLM-Z1 0.669/0.112/0.216/0.633; Qwen3 Non-thinking 0.604/0.257/0.296/0.588 vs. Thinking 0.658/0.118/0.217/0.664.
  - AUROC counterexamples: GLM-4 on the two Math subsets and EXAONE-3.5 on SuperGPQA Non-Math have higher AUROC than their reasoning counterparts; the authors attribute this to multiple-choice options providing implicit correctness cues, with non-reasoning models using almost only the 95%/85% bins, artificially inflating AUROC (Sec. 3.2).
- **CoT progress (Table 3)**: for reasoning models the ECE/Brier slopes are significantly negative and the AUROC slope is significantly positive (e.g. GLM-Z1 TriviaQA ECE −0.016, Brier −0.011, AUROC +0.026); non-reasoning models mostly show no significant trend or get worse.
- **Ablations (Table 4, R1-Distill, TriviaQA ECE/Brier/AUROC)**: Original 0.042/0.157/0.782; −Confidence Reasoning 0.063/0.166/0.763; −Epistemic Markers 0.109/0.154/0.837 (ECE worsens but AUROC rises, the model using almost only the 95%/65% bins); −Non-linear Reasoning 0.161/0.179/0.734; No CoT 0.150/0.206/0.689. Conclusion: non-linear reasoning (exploration/backtracking) has the largest effect.
- **ICL slow thinking (Table 5)**: GLM-4-32B TriviaQA ECE 0.150→0.029, AUROC 0.631→0.796; Qwen2.5-32B-Inst AUROC 0.714→0.784.
- **Expression format (Table 7/8)**: with language-only descriptions, reasoning models still dominate across the board; with direct numeric probability output, calibration worsens for both kinds of models (e.g. Qwen3 Thinking TriviaQA ECE 0.063→0.169), but reasoning models are still generally better.
- **Sampling (Table 9)**: R1-Distill with T=0.6, five runs: TriviaQA ECE 0.070±0.001, Brier 0.170±0.001, AUROC 0.767±0.001 (slightly below Qwen2.5-Inst 0.769, which the authors explain by a more dispersed confidence distribution).
- **Sec. 5**: budget forcing does not necessarily improve calibration; the calibration gap between reasoning and non-reasoning grows with model scale; reasoning models still rarely give confidence <55%.

## 6. Fit to this project's unified benchmark
- **Applicability**: high. Fully black-box and text-only; Qwen3 (Thinking mode) is itself one of the paper's evaluated models (32B), and Qwen3-8B thinking via vLLM can directly reuse the `reasoning_no_force` pipeline (README: Qwen3 needs no forced confidence reasoning). It does not depend on top-k logprobs, so there is no top-k truncation proxy issue.
- **Differences from the paper / needed adaptations**:
  1. The paper's "Math" is multiple-choice calculation questions (MMLU-Pro calc / SuperGPQA calc-middle), not free-form competition math; this project's long-CoT math (GSM8K/MATH/AIME-like) requires changing `**Answer**: $ANSWER` to a format checkable by rule-based tools such as math-verify (e.g. require `\boxed{}`, or directly judge mathematical equivalence on the text after `**Answer**:`); this is a modification of the prompt and must be noted in the report.
  2. Correctness judgment: the paper uses GPT-4o-mini + the SimpleQA grader, whose rule for numbers is "only correct to the last significant digit of gold" (e.g. 124k is judged correct when gold is 120k), which is lenient for math problems; this project should uniformly use a rule-based math verifier rather than copy the judge.
  3. **Generation budget**: the paper caps thinking at only 4096/8192 tokens, and the code forcibly appends `\n</think>\n\n**Answer**:` at `</think>` or when the cap is reached to obtain the answer and confidence; for Qwen3-8B on AIME-level problems, many trajectories would be truncated yet still "forced to answer". We recommend using Qwen3's officially recommended long budget (e.g. 32k), recording truncation flags, and using the same truncation handling as the other baselines.
  4. **Decoding**: the paper's main experiments are greedy; Qwen3 officially does not recommend greedy for thinking mode (prone to repetition). If this benchmark scores multiple sampled trajectories, a unified sampling setup should be used (Qwen3 recommends T=0.6, top-p=0.95, top-k=20); the paper only verifies in App. A.2.3 that the conclusion is stable at T=0.6 for R1-Distill.
  5. **This prompt changes the reasoning trajectory itself** (it asks the model to assess confidence inside think), so in a faithful implementation the trajectories/accuracy of LRMVerbal differ from those of the other baselines that "generate under the original prompt and score post hoc". Two options: (a) faithful version - generate trajectories separately with the Listing 1 prompt and label them with their own answers; (b) shared-trajectory proxy version - after the already generated original thinking, append `</think>` + a confidence query (similar to the early-termination trick of Sec. 4.1) and do only one short completion. (b) facilitates paired comparison with other baselines on the same trajectories, but is not the original definition and must be labeled as a proxy.
  6. **Two-stage completion implementation**: vLLM needs raw-text completion (`tokenizer.apply_chat_template(..., enable_thinking=True)` + first-turn thinking + `\n</think>\n\n**Answer**:`), not the chat API; with prefix caching enabled, the cost of the second stage is small.
- **Parse-failure handling**: the original code directly drops unparseable confidences (affecting only the confidence metrics, not accuracy), which creates selection bias. This benchmark should give a score for every sample: we recommend reporting the parse-failure rate and applying a fixed fallback to failed samples (e.g. force one more completion; if it still fails, record the lowest bin 0.05 or 0.5, fixed in advance and consistent across the whole benchmark). It must also handle formats such as `\text{Almost certain}`, `$...$`, and underscores (the notebook's `clean_confidence` handles these).
- **Discrete scores and AUROC ties**: there are only 10 values, and reasoning models rarely give <55% (Sec. 5), so in practice scores often concentrate on 3-4 bins; AUROC/AURC then have many ties (sklearn counts ties as 0.5). The paper itself points out that concentrating on two bins can instead inflate AUROC (Sec. 3.2, Table 4 −Epistemic, Table 9), so AUROC is sensitive to binning behavior. We recommend also reporting ECE (10 equal-width bins, consistent with the paper), Brier, AUROC, and the confidence histogram; do not break ties with other signals (otherwise it is no longer the original method).
- **Scale**: all main results in the paper are for 32B; Sec. 5 shows that the reasoning/non-reasoning gap grows with scale, and the verbal calibration of 8B models may be clearly weaker (prone to collapsing to "Almost certain").
- **Per-question cost**: per trajectory, 1 full thinking generation (including extra confidence-reasoning tokens, length not reported) + 1 completion of <=64 tokens; no multiple sampling, no logprobs, and no extra model (if a rule-based verifier replaces the GPT-4o-mini judge).
- **Recommended faithful implementation setup**: Listing 1 prompt (placed before the question) + supplementary math answer format instructions; Qwen3 `enable_thinking=True`, no forced confidence reasoning; after generating up to `</think>`, append `\n</think>\n\n**Answer**:` and greedily complete 64 tokens (consistent with the code); bin→midpoint mapping 0.05…0.95; ECE with 10 equal-width bins; keep all samples (parse failures follow the pre-set fallback).
- **Red flags / notes**:
  - **All main-table numbers for Qwen3 Thinking are identical to QwQ** (Acc/ECE/Brier/AUROC match item by item in Tables 1, 2, 6, 11, 12, e.g. both are 0.768/0.063/0.137/0.807 on TriviaQA; arXiv v2 and the NeurIPS proceedings version are the same), a suspected copy error; the Qwen3 Thinking numbers in Tables 7/8 differ from these. Therefore the paper's main results for Qwen3 Thinking cannot serve as reproduction reference values.
  - "33/36 settings strictly better on all metrics" is not fully consistent with the appendix ECE: on MMLU-Pro Math, R1-Distill ECE 0.105 > Qwen2.5-Inst 0.094 and GLM-Z1 0.072 > GLM-4 0.067 (Table 12).
  - The non-reasoning baseline rows in Table 5 are identical to the "+Two-turn" rows in Table 6 (e.g. Qwen2.5-32B-Inst TriviaQA 0.709/0.135/0.192/0.714), i.e. the ICL slow-thinking comparison uses the two-turn setting rather than the main setting.
  - The paper (App. B.2) says the second-turn completion is performed only on format failure, while the code does it for every sample; the final sentence of the paper's Listing 1 differs from the code's prompt.
  - The code repository has no LICENSE file; the code for some variants in Appendix A.2 is not found.
