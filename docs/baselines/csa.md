# CSA: Clustered Self-Assessment: A Simple yet Effective Method for Uncertainty Quantification in Large Language Models

> This note records a reading of the original paper and the official implementation; for the adaptation and settings currently used in this repo, see the [experimental protocol](../protocol.md).
- Paper: Findings of the Association for Computational Linguistics: ACL 2026, pp. 30666–30680 (July 2–7, 2026; the official README gives arXiv:2606.03846 and the ACL Anthology https://aclanthology.org/2026.findings-acl.1531/ , both recorded only from the official README and not independently opened and checked); Qi Cao, Takeshi Kojima, Andrew Gambardella, Helinyi Peng, Yutaka Matsuo, Yusuke Iwasawa (The University of Tokyo)
- Official code: https://github.com/ccqq77/clustered_self_assessment (**no license declared** (GitHub API license=null, no LICENSE file in the repo, raw 404); PyTorch 2.7 + Transformers 4.53 + FlashAttention-2 + sentence-transformers CrossEncoder; verified to contain `generate.py, answer_clustering.py, self_assessment.py, score.py, data.py, requirements.txt`; usable, the three-step pipeline is complete; last push 2026-07-11, commit "Update README"; answer_clustering.py/data.py state they are adapted from zlin7/UQ-NLG)
- Category: multi-sample semantic consistency + self-assessment (a P(True) variant in MCQ form, single-token probability); response-level (gives a confidence probability to the specific response being evaluated)
- Access requirements: gray-box (needs the softmax probability of the label token ("A","B",...) at the last position, i.e. the token probability normalized over the full vocabulary; with vLLM top-k logprobs it suffices that A is within the top-k, and "A" is usually top-1, so it is feasible in practice); no training, no labels (the probe in main text §4.6 is an additional application); needs an extra model: NLI (`microsoft/deberta-large-mnli`, the official default); GPT-4.1 as judge at evaluation.

## 1. Method design
- Core idea (§3, Fig.1): two stages. (1) Answer Clustering: for each question, merge the "answer to be evaluated" (set to the greedy answer in the paper) with N additional temperature-sampled answers and cluster them into semantically distinct clusters with NLI; (2) Self-Assessment: take one representative answer per cluster as an MCQ option, append a "None of the above" option, give this MCQ to the original LLM, and read the token probability the model assigns to "the option containing the answer to be evaluated" (label "A") as the confidence.
- Clustering (§3.1, official `answer_clustering.py`): answers are processed in a fixed order, with the **first being the answer to be evaluated (greedy)**; bidirectional NLI (deberta-large-mnli) is run on each pair of answers; clusters and representatives (the first answer in the cluster) are maintained, a new answer is compared with each representative and merged into the first cluster satisfying the condition, otherwise a new cluster is created. Condition in the paper's text: in the bidirectional NLI results, "no contradiction, or entailment in both directions". Official code implementation: the sum of the `argmax` labels (0=contradiction, 1=neutral, 2=entailment) over the two directions ≥ 2 counts as the same cluster (this rule also merges the (contradiction, entailment) combination into one cluster, which is looser than the paper's text; **not verified empirically; a place where code and paper may be inconsistent**). Empty-string answers are filtered; if the evaluated answer is empty, the score is 0.
- MCQ construction and scoring (§3.2, `self_assessment.py`, `data.py`): option labels A, B, C, ..., with "None of the above" as the last option. The QA prompt (zero-shot, for base models) is "Task:\nSelect the one correct answer to the question from the choices provided. If none of the provided choices is correct, select the final choice ({none_label}) None of the above.\n\nQuestion:\n{question}\n\nChoices:\n(A) ...\n(B) ...\n...\n\nAnswer:\nThe answer is (" (for XSum, "The summary is ("). Take the logits at the last token position, apply softmax over the **entire vocabulary**, and take the probability of each label token; the confidence is S = P(label "A"), i.e. the probability of the option corresponding to the evaluated answer (Eq. (1)(2), no renormalization among the options).
- Scoring: S ∈ [0,1], naturally a probability (the paper uses Brier to evaluate calibration in §4.5 and does no post-hoc calibration, see Limitations); larger means more confident (S is used directly as the AUROC predictor of correctness).
- Key hyperparameters: number of additional samples N (8 in the main experiments; range 2/4/8/16); sampling τ=0.5, top-k=32, top-p=0.95 (App. A.1, following the effective settings of EigenScore/SE); NLI default deberta-large-mnli (v2-xlarge/xxlarge are almost identical, Table 4); option order (Original = evaluated answer placed at A / Reverse / Random, differences are very small in Table 3).
- Additional: §4.6 uses the CSA score as a training signal to train a hidden-state probe (logistic regression, L1 regularization C=0.1, hidden state of the second-to-last generated token, 70% of TQA for training, 30% of TQA as ID test and NQ as OOD test; soft label or binarized at a 0.5 threshold), compared with SEP and an accuracy probe (Fig.4, Brier); this is an additional application, not the main subject to be reproduced in this benchmark.

## 2. Dataset settings (§4.1)
- TriviaQA (TQA, using Lin et al. 2024 preprocessing: 9,960 questions), Natural Questions (NQ, 3,610 questions); supplementary XSum (LM-Polygraph's 11,334 test samples, summarization task).
- Generation prompts follow Lin et al. and LM-Polygraph: TQA uses "Answer these questions:\nQuestion: In Scotland a bothy/bothie is a? Answer: House ..." (1-shot); NQ is 5-shot (drawn from the training set with fixed seed 42); XSum uses "Here's the text and it's short one-sentence summary.\n\nText: ... Summary (one sentence):".
- Correctness: GPT-4.1 (2025-04-14 version) as LLM-as-a-Judge, judging directly by real-world facts whether the response is correct (reference answers as an aid; outputs a single token True/False; for XSum it judges whether the summary is correct relative to the source text); the paper says heuristics were abandoned because ROUGE-L/semantic-similarity thresholds are unreliable (citing Santilli et al. 2024). Human agreement rate of the judge: not reported in the paper.

## 3. Experimental protocol
- The evaluated answer is the single response generated by greedy decoding (temperature 0, max_new_tokens=256) ("our objective is to quantify the uncertainty associated with generations produced by greedy decoding", App. A.1); the additional samples are 2–16 generated with τ=0.5, top-k 32, top-p 0.95.
- No training (main method); see above for the probe experiments.
- Metrics: AUROC (main; Fig.2, Table 1, Tables 7–11); Brier score (calibration, Table 2, compared with P(True), Probability, NSE (normalized SE scaled to [0,1] by the number of clusters)); the probe uses Brier.
- Baselines (Fig.2 / Tables 7–11): Perplexity, Probability, P(True), Predictive Entropy, LN-Entropy, Semantic Entropy, Ecc/EigV/Deg, tokenSAR/sentenceSAR/SAR, EigenScore. Sampling-based baselines use the same 8 additional samples.
- Seeds/statistics: not reported (single-run results, no confidence intervals). Compute cost: the paper says the main cost is the additional sampling, the NLI model is lightweight, and MCQ scoring needs only one forward pass to take the logits of one token (§4.3); concrete GPU time is not reported.

## 4. LLM backbone settings (§4.1)
- 7 models: Qwen2.5-7B / 14B / 32B; Qwen3-14B and Qwen3-30B-A3B (**Base versions**, not thinking/instruct); Gemma-3-12B / 27B (**pt versions**). All are pretrained base models, using flash-attention-2, `torch_dtype="auto"`; max_new_tokens=256. Non-reasoning / non-CoT. Context length not reported.

## 5. Main results and conclusions (brief, key numbers)
- Main table Table 1/9 (8 additional samples, AUROC): CSA on TQA 0.927/0.936/0.940/0.935/0.933/0.930/0.924 (in model order), on NQ 0.846/0.837/0.850/0.853/0.840/0.843/0.821. Baselines for comparison (TQA, Qwen2.5-32B): Probability 0.883, SE 0.844, EigV 0.865, Deg 0.848, SAR 0.882, P(True) 0.890; on NQ SE 0.799, EigV 0.806, P(True) 0.785, SAR 0.769. XSum (Table 11): CSA 0.751/0.739/0.797/0.806/0.781/0.728/0.713 vs SE 0.677/0.662/0.697/0.679/0.707/0.564/0.563, EigV 0.688/0.681/0.706/0.692/0.709/0.588/0.585.
- Ablations (Table 1): removing clustering (raw sampled answers used directly as options) drops TQA to 0.874–0.914; removing sampling (only the evaluated answer and None remain, i.e. degenerating to P(True)) drops to 0.737–0.890 on TQA and 0.609–0.799 on NQ.
- Sample efficiency (Fig.3, Tables 7–10): with only 2 additional samples it matches baselines that need 16.
- Calibration (Table 2, Brier, lower is better): CSA on TQA 0.0721–0.1183, P(True) 0.1172–0.2147, Probability 0.1674–0.2402, NSE 0.0937–0.1580.
- Sensitivity (App. B): NLI model size and option order have little effect (Tables 3/4); sampling temperature 0.5–0.75 is best, 1.0 is slightly lower (Table 5, e.g. NQ Qwen2.5-7B 0.846 → 0.835); embedding clustering (OpenAI/MPNet/Self, threshold/k-means) is overall worse than NLI (Table 6).
- Authors' limitations (§6): needs logits; depends on an external NLI; no post-hoc calibration.

## 6. Fit to this project's unified benchmark
- The features closest to this benchmark: response-level (gives a [0,1] probability for one specific response), gray-box needing only one token's probability, with extra cost mainly K−1 samples + one short forward pass. Core adaptation points:
  1. Clustering: replace NLI with math_verify final-answer equivalence (NLI on whole long-CoT responses is infeasible); each cluster's "option text" = the final answer of that cluster's representative (suggest writing only the final answer/expression, without CoT).
  2. Evaluated object: the paper evaluates the greedy answer; greedy is not recommended for Qwen3 thinking mode, so the suggestion is to put the "evaluated (main) response" at option A, deduplicate and cluster the answers of the other K−1 samples as the remaining options, and finally add "None of the above" (consistent with the paper's "Original order"; Table 3 shows Reverse/Random differ very little, but note the position prior of A, and an order-randomization ablation can be run).
  3. How to call the model in the self-assessment stage: the paper uses a **base model**, a zero-shot MCQ, and takes the next-token probability directly after "The answer is (". Qwen3 thinking is a chat model, so apply the chat template, put the MCQ as a user message, and for the assistant disable thinking (`enable_thinking=False`, or prefill an empty think block) + prefill "The answer is (" and read the logprob of the next token; if the model is made to think first and then answer, it becomes a different method (no longer a single-token probability, not comparable with the paper's numbers). This is an adaptation rather than the original setting and must be labeled in the benchmark.
  4. Probability: the paper uses the label-token probability under the full-vocabulary softmax (no renormalization among options); vLLM's `logprobs=k` returns full-vocabulary-normalized logprobs, so the logprob of "A" can be taken directly; if A is not in the top-k, treat it as very low probability (or fetch it with `allowed_token_ids`/prompt_logprobs).
- Extra cost per question: K−1 full long-CoT samples (the paper uses at least 2, 8 in the main experiments; reusable if shared with SE/KLE sampling) + 1 MCQ forward pass (prompt + options only, hundreds of tokens, **no generation**) + cluster-count² answer-level matches (no NLI). The extra cost is almost the same as for SE-type methods, but it provides a response-level probability.
- Pitfalls: (1) the paper is validated only on short-answer QA/summarization + 7 base models, and **math/long-CoT/reasoning models/Qwen3 thinking are not validated at all**; the paper's conclusion that "2 additional samples suffice" need not hold for math with multiple solution methods and multiple answers; (2) the paper evaluates greedy responses, whereas this benchmark evaluates sampled (T≈0.6) responses; (3) the official code's default NLI clustering rule may differ slightly from the paper's text description (see above), which is unaffected after the math adaptation; (4) the official repo has no license, so use it only as a reference implementation, and rewriting the MCQ part yourself is recommended (the logic is very short); (5) for questions with only 1 cluster (all sampled answers agree), the MCQ has only [answer, None] and degenerates to P(True) (the paper's "w/o sampling" ablation is exactly this case; AUROC may be low here, but in math all samples agreeing usually means high accuracy, so see the measured results); (6) writing the full CoT into the options would be too long and would leak differences in reasoning paths, so only the final answer must be written; (7) sampling temperature τ=0.5 is best (Table 5), and the recommended 0.6 for Qwen3 thinking is compatible.
- Recommended faithful implementation: N=8 (with ablations at N=2,4,16), sampling T≈0.5–0.6, top-p 0.95, top-k 32/20; answer-equivalence clustering; evaluated answer placed at A; MCQ prompt follows the paper's English template verbatim (only replacing Question with the math problem, with the final answers as options); confidence = P("A"); report AUROC and Brier (the paper emphasizes its calibration).
