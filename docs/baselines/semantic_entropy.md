- Category: multi-sample semantic consistency (question-level uncertainty; the Nature version provides both discrete and likelihood-weighted variants)
- Access requirements: gray-box/black-box. Discrete SE needs only M sampled texts (pure black-box); likelihood-weighted SE needs the token logprobs of each sampled sequence (only the logprob of the sampled tokens, not the full vocabulary or top-k). No training, no labels. Requires an extra model: an entailment judge (NLI: DeBERTa-large/xlarge-MNLI, or GPT-3.5/GPT-4/LLaMA as the entailment judge). Correctness judgment needs a GPT-4 judge / SQuAD F1 / Rouge-L (evaluation only).

## 1. Method design
- Core idea: sample M answers for the same prompt x, use bidirectional entailment to group answers with the same meaning into one semantic cluster, then compute entropy over "semantic clusters" rather than "token sequences", which avoids inflated entropy from paraphrases.
- Pipeline (Nature Methods "Principles of semantic uncertainty"): 1) Generation: sample M answers; 2) Clustering: bidirectional-entailment clustering (Extended Data Fig.1 / Kuhn App. A.2 Algorithm 1: compare each sequence in turn with the first member of every existing cluster; merge if equivalent, otherwise open a new cluster; by transitivity only cluster representatives need to be compared); 3) compute the entropy over clusters.
- Equivalence relation: sequences s and s' are equivalent only if they entail each other in the context (the question). The DeBERTa version treats "question + answer" as one sentence and checks whether question+s and question+s' are both entailment in both directions (Kuhn §4 Step 2; Nature Methods "Entailment estimator"). LLM-version prompt: "We are evaluating answers to the question {question} Here are two possible answers: Possible Answer 1: ... Possible Answer 2: ... Does Possible Answer 1 semantically entail Possible Answer 2? Respond with entailment, contradiction, or neutral." (Nature finally chose GPT-3.5 as the entailment estimator for sentence-length answers, Methods + Supp. Note 2).
- Clustering criterion in the official code (`get_semantic_ids`): by default (strict_entailment=False) it is "neither direction is contradiction, and not both neutral" (looser than the strict bidirectional entailment in the paper text); only `--strict_entailment` gives strict bidirectional entailment. The default NLI model is `microsoft/deberta-v2-xlarge-mnli` (the paper says DeBERTa-large, 1.5B), and there is a `--condition_on_question` option.
- Score formulas (the formulas in the paper md are images and were lost; the following is checked against the paper text and the official code):
  - Cluster probability: P(C_i|x) = Σ_{s∈C_i} P(s|x) (Kuhn Eq.2).
  - **(a) ICLR 2023 original**: SE(x) ≈ −(1/|C|) Σ_{i=1}^{|C|} log P(C_i|x), i.e. a Monte-Carlo average over the sampled clusters; log P(s|x) can be length-normalized (mean token logprob; Kuhn §3.3, matters a lot for CoQA in §6.1). Code `get_predictive_entropy_over_concepts`: logsumexp of the sample log-likelihoods within each cluster, then −mean. Cluster probabilities are not normalized (`unnormalised_entropy_over_concepts` in the code is a variant without length normalization).
  - **(b) Nature 2024 (main method, "semantic entropy")**: Rao–Blackwellized estimate SE(x) ≈ −Σ_i P(C_i|x) log P(C_i|x), where P(C_i|x) is first obtained by summing the (length-normalized) sequence likelihoods of the M samples per cluster, then divided by the sum over all clusters to form a categorical distribution Σ_i P(C_i|x)=1 (Methods: "Without this normalization step cluster 'probabilities' could exceed one because of length normalization, resulting in degeneracies."). Code: `logsumexp_by_id(..., agg='sum_normalized')` + `predictive_entropy_rao`; log_liks_agg = mean of the token logprobs of each sample (length normalization).
  - **Discrete SE (Nature Methods "discrete semantic entropy")**: P(C_i|x) ≈ (number of samples in cluster i)/M, SE_disc = −Σ_i (n_i/M) log(n_i/M); it uses no token probabilities and ignores likelihoods (equivalent to assuming every sample is equally probable). It converges to the likelihood version as M→∞. Paper: "discrete semantic entropy results in similar performance empirically". Code: `cluster_assignment_entropy`. All GPT-4 paragraph experiments use the discrete version.
  - Other baselines included: naive/predictive entropy (entropy of the length-normalized joint probability; `predictive_entropy` in the code = −mean(mean-token-logprob)), P(True), embedding regression (supervised, logistic regression on the last hidden state).
- Hyperparameters: M=10 samples (Nature "We use ten generations to compute entropy", Supp. Fig.2; Kuhn App. B: >10 gives no significant improvement); sampling temperature T=1.0 + nucleus p=0.9 + top-k=50 (Nature Methods "Generating a set of answers"); the "best answer" used for correctness judgment is a separate single generation at T=0.1 (Nature), while Kuhn uses beam search (num_beams=5, do_sample=True) to get the most likely answer; Kuhn's sampling-temperature ablation over {0.25,0.5,1.0,1.5} finds 0.5 best (Fig. 3b, Fig. 4, Table 4: beam multinomial sampling is worse than multinomial). Official code defaults: temperature=1.0, num_generations=10, num_few_shot=5, model_max_new_tokens=50, num_samples=400.
- Scoring target: **question-level** (entropy of the sampling distribution for x), not a score for any specific answer; at evaluation the entropy is used to predict whether the "best answer (single low-temperature generation)" is wrong. Output range [0, log M] (discrete version); not a probability; larger means more uncertain.
- Paragraph-level extension (Nature Fig.1b, Methods "Detecting confabulations in biographies"): GPT-4 decomposes the paragraph into factoids → generates 6 questions per factoid (two prompts, 3 each) → regenerates 3 answers per question + the original factoid → clusters with DeBERTa (not a GPT judge; the looser "at least one entails the other and neither contradicts" rule) → discrete SE → averaged over questions.

## 2. Dataset settings
- Nature (sentence-length, Methods "Tasks"): BioASQ (2023 Task 11B biomedical QA), SQuAD 1.1 (no context given, closed-book), TriviaQA, NQ-Open, SVAMP (grade-school math word problems); each dataset randomly sampled to 400 train + 400 test (SE itself does not use train; the supervised baseline does). No context is provided to avoid overly high accuracy. Answers are free text (single sentence, "Answer the following question in a single brief but complete sentence."). Correctness label: GPT-4 compares the answer with the reference answer (prompt: "...does the proposed answer mean the same as the expected answer? Respond only with yes or no.", changed to "...mean the same as any of the expected answers?" when there are multiple references), checked against humans in Supp. Note 6; the short-phrase setting (Supp. Note 7) uses SQuAD F1>0.5.
- Nature paragraph-level: FactualBio (21 people, biographies generated by GPT-4 v0613, 150 factual claims, 45 of them wrong, human-annotated).
- Kuhn ICLR 2023: CoQA (open-book conversational QA, dev split ~8000 questions), TriviaQA (closed-book, 8000 questions sampled from the train split); correctness: Rouge-L(s, ref) > 0.3 (App. B.3 also tests exact match and Rouge-1; conclusions are robust); TriviaQA uses a 10-shot prompt, CoQA zero-shot; TriviaQA accuracy 50.6%, CoQA 82.3% (§6.1). 300 human annotations check the equivalence judgments, accuracy TriviaQA 92.7% / CoQA 95.5% (§4).
- Math reasoning: only SVAMP (short CoT/short answers, sentence-length setting); **no** GSM8K/MATH/AIME/long-CoT experiments.

## 3. Experimental protocol
- No training (SE is unsupervised); the supervised baseline embedding regression is trained on 400 train questions, and the OOD setting trains on 4 off-distribution datasets. P(True) uses at most 20 few-shot examples (fewer when limited by context).
- Generation: Nature uses 10 samples at T=1.0 + 1 best answer at T=0.1 per question; official code `model_max_new_tokens=50`. Kuhn: multinomial sampling, 10 samples/question, with 30B OPT as the headline result.
- Metrics: AUROC (predicting whether the answer is wrong; Nature takes "incorrect" as the positive class; Kuhn predicts correctness from uncertainty), AURAC (area under the rejection-accuracy curve, newly proposed in Nature), rejection accuracy@X% (80/90/95/100%). Kuhn explicitly argues that Brier/calibration do not apply to free text (§6 "Performance evaluation").
- Statistics: the Nature summary figure reports raw averages across datasets without standard error ("We report the raw average score across held-out evaluation datasets without standard error"); the number of seeds is not reported (code random_seed defaults to 10).
- Compute cost: M=10 generations per question + at most C(M,2) bidirectional NLI calls (by transitivity only cluster representatives are compared); Kuhn: DeBERTa-large 1.5B is far smaller than the generation model, so clustering cost is negligible relative to generation; Nature Supp. Note 3 discusses cost (the local md does not include the Supplementary). Kuhn's experiments ran on 80GB A100s.

## 4. LLM backbone settings
- Nature: LLaMA 2 Chat 7B/13B/70B, Falcon Instruct 7B/40B, Mistral Instruct 7B (sentence-length, 30 task×model combinations in total); paragraph-level uses GPT-4 (v0613, no logprobs, so discrete only). Precision/framework/context: not reported in the main text; the official code uses HF transformers.
- Kuhn: OPT 2.7B / 6.7B / 13B / 30B (pretrained base, not fine-tuned, no ensemble); HF transformers.
- All are non-reasoning models with short answers.

## 5. Main results and conclusions (brief, key numbers)
- Nature (Fig. 2 and main text): average AUROC over 30 task×model combinations: semantic entropy 0.790, naive entropy 0.691, P(True) 0.698, embedding regression 0.687; SE stays stable at 0.78–0.81 across model families and scales. Discrete SE performs similarly to standard SE ("performs similarly", no specific difference given). SE beats embedding regression under OOD (the latter degrades OOD).
- Nature paragraph-level GPT-4 (Fig.3): the AUROC/AURAC of discrete SE are both significantly higher than the P(True) variants and the self-check baseline (specific values only in the figure, not given in the local md); P(True) is slightly better after rejecting the first 20%.
- Kuhn (§6.1, Fig. 1/2, Table 2): on 30B OPT the AUROC of SE is significantly better than predictive entropy (with/without length normalization), lexical similarity, and P(True); SE gains more advantage as model size grows; Table 2: average number of semantic clusters, correct vs incorrect: CoQA 1.27 vs 1.77, TriviaQA 1.89 vs 3.89; AUROC: SE 0.77 / cluster count 0.66 (CoQA), SE 0.83 / cluster count 0.79 (TriviaQA). Fig.3a: SE gains more as the number of samples increases; Fig.3b: best temperature 0.5.
- Authors' limitation (Nature Discussion): only detects confabulation (arbitrary/random errors); cannot find systematic errors (consistently wrong), so it is ineffective for "confidently wrong".

## 6. Fit to this project's unified benchmark
- Applicability: for long-CoT math, "semantic clustering" must be replaced by "final-answer equivalence clustering" (math_verify decides whether boxed answers are equivalent). This is essentially the answer-entropy / self-consistency entropy commonly mentioned in the community, and is the most natural implementation of discrete SE; NLI is no longer needed. The CoT content must be dropped before clustering and only the final answers compared (NLI over a whole CoT is meaningless and too long).
- Extra cost: K−1 (K≈10, paper M=10) full long-CoT samples (expensive, ~10x generation per question); 0 extra forwards (discrete), clustering runs on CPU. For the likelihood-weighted version, vLLM only needs to return the logprobs of the sampled tokens (`logprobs=0/1` includes the logprob of the sampled token; nothing beyond the full vocabulary/top-k is needed); no extra model.
- Trade-off between the two variants: (1) discrete SE (recommended as the main one; robust, "similar" to the Nature results); (2) likelihood-weighted (Nature version: length-normalized mean-token-logprob, then logsumexp per cluster and normalization). Note that with long CoTs of thousands of tokens the differences in mean-token-logprob are tiny, and sampling with top-p/temperature≠1 makes the logprob not correspond to the true sampling distribution (whether vLLM returns pre- or post-processing logprobs depends on `logprobs_mode`), which must be recorded explicitly; Kuhn's original (−mean log P(C_i), unnormalized) differs from the Nature version; we recommend implementing the Nature version and labelling the Kuhn version as an "SE-ICLR23" variant, or skipping it.
- Scoring-target mismatch: SE is question-level, so all answers to the same question get the same score; when the unified benchmark evaluates "per-answer correctness", one evaluated answer must be fixed (the paper uses a single greedy-ish answer at T=0.1, separate from the 10 T=1.0 samples). To get a response-level score one can add "the share of the cluster containing that answer / P(C(ŝ))" (this is the idea of the C-type variants in the EigV paper, not original SE). Within-question AUROC is uninformative; only across questions.
- Pitfalls: (1) A different clustering criterion changes the numbers: the paper text says strict bidirectional entailment, while the official code defaults to the looser rule (no contradiction and not [neutral, neutral]); for math, answer equivalence is what is filled in, so this should not matter. (2) Sampling settings: paper T=1.0, top-p=0.9, top-k=50; Qwen3 thinking recommends T=0.6, top-p=0.95, top-k=20; we need to decide whether to follow the model's recommended settings and keep them unified across all multi-sample methods in the benchmark. (3) Truncated/no-answer samples need their own cluster ("no answer" forms its own cluster or is treated as maximum uncertainty); for GPT-4 refusals the official code has the rule "if more than half contain not available/unknown/unclear, take maximum uncertainty". (4) For "consistently wrong" questions SE=0 but the answer is wrong; long-CoT math may have many systematic errors, which will lower AUROC.
- Recommended faithful implementation: M=10 (an ablation over M∈{5,10,16} is possible), discrete SE = entropy of the empirical distribution over answer clusters (natural log); likelihood-weighted SE as an additional row (mean-token-logprob, logsumexp within clusters, normalization across clusters).
