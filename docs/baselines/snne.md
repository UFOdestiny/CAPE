# SNNE: Beyond Semantic Entropy: Boosting LLM Uncertainty Quantification with Pairwise Semantic Similarity (Semantic Nearest Neighbor Entropy, including WSNNE)

> This note records a reading of the original paper and the official implementation; for the adaptation and settings currently used in this repo, see the [experimental protocol](../protocol.md).
- Paper: Findings of the Association for Computational Linguistics: ACL 2025, pp. 4530–4540 (arXiv:2506.00245), https://arxiv.org/abs/2506.00245 ; Dang Nguyen (UCLA CS), Ali Payani (Cisco Systems), Baharan Mirzasoleiman (UCLA CS)
- Official code: https://github.com/BigML-CS-UCLA/SNNE (MIT; PyTorch + HF transformers + sentence-transformers + wandb, adapted from jlko/semantic_uncertainty; verified to contain `snne/compute_snne.py`, `snne/uncertainty/utils/entropy_utils.py` (the `snne()` implementation), `compute_kle.py`, `compute_graph_baselines.py`, `compute_sar.py`, `compute_luq.py`, `scripts/`; usable; last commit 2025-06-09). **Note**: the link in the paper abstract, `github.com/BigML-CSUCLA/SNNE`, returns 404; the actual repo is `BigML-CS-UCLA/SNNE` (with a hyphen), whose README calls itself the "official implementation of our ACL Findings 2025 paper".
- Category: multi-sample semantic consistency (question-level; uses pairwise continuous similarity + LogSumExp, no clustering)
- Access requirements: SNNE is purely black-box (only needs the n sampled texts); WSNNE needs the (length-normalized) token probabilities of the sampled sequences (gray-box, only the logprob of the sampled tokens). No training, no labels. The extra model depends on the similarity function f: ROUGE-L (no model needed, the paper's main setting) / DeBERTa NLI (entail) / sentence embeddings (embed: App. C of the paper uses a Qwen2-7B-instruct-type embedding model; the official code defaults to `Alibaba-NLP/gte-Qwen2-7B-instruct`, max_seq_length 8192, with `Salesforce/SFR-Embedding-2_R` as an alternative).

## 1. Method design
- Motivation (§1, §3): SE uses only hard clustering and ignores intra-cluster similarity (dispersion within a cluster) and inter-cluster similarity (distance between clusters). Single-sentence responses of modern LLMs are longer (Llama-3.1-8B / Phi-3-mini average 4.1 / 4.9 words over 5 QA datasets, Llama2-7B 2.3 words), and the Spearman correlation between average response length and the number of semantic clusters is 0.83 (Fig.1 left, Llama-3.1-8B on SQuAD); when the number of clusters M→n, DSE tends to a constant (no discriminative power).
- **SNNE formula (§4 Eq. (3); the paper's equation is an image in the local md and was lost, so it is reconstructed from the paper's text and checked against the official `snne()` code)**: SNNE(q) = −(1/n) Σ_{i=1}^n log Σ_{j=1}^n exp( f(a^i, a^j | q) / τ ). f is the similarity of two answers given the question; the inner Σ_j covers both intra-cluster and inter-cluster similarity, and LogSumExp is a smooth approximation of max (analogous to nearest-neighbor entropy estimation, Beirlant et al. 1997), reducing sensitivity to outlier responses (in contrast to graph methods, which aggregate by summation). The official code defaults to `selfsim=True` (includes the j=i self-similarity term), `variant='only_denom'` (the formula above), and loss `-(logsumexp * weight).mean()`; larger values mean more uncertain.
- **WSNNE (white-box, Eq. (4))**: weights by the normalized length-normalized sequence probability: WSNNE = −(1/n) Σ_i w_i · log Σ_j exp(f(a^i,a^j|q)/τ), w_i ∝ P̃(a^i|q) (length-normalized sequence probability P̃ = P/len, P̄ = P̃/Σ_j P̃_j). Official code: `weight_pe = exp(loglik)`; `weight_pe / weight_pe.mean()` (i.e. n·P̄, making the mean weight 1).
- Theory: Thm 4.1: if f(a^i,a^j|q) = τ·log(1/n) if and only if a^i,a^j are in the same cluster, and −∞ otherwise, then SNNE ≡ DSE; Thm 4.2: if f = τ·log(P̃(a^j|q)/Q) (Q=Σ_i P̃(a^i|q)) within a cluster and −∞ otherwise, then WSNNE ≡ SE. As τ→0, LUQ-Pair can be recovered in the one-sentence-output setting.
- Similarity function f (§4 "Choices of similarity function"): ROUGE-L / NLI (DeBERTa entailment score) / sentence-embedding cosine. Hyperparameter setting in the paper (App. B): "For similarity function f, we use ROUGE-L score"; the official QA script `compute_snne.sh` sets `CONCAT=True` for QA (concatenating the question before the answer before computing similarity; False for summarization/translation); the NLI/embedding variants are ablations (App. C.1 Table 5, and that table covers only TS/MT).
- Hyperparameters: τ ∈ {0.1, 1, 10, 100}, default τ=1 (Table 6 shows insensitivity to τ, "Overall, τ = 1 yields the best performance"); n=10 samples, T=1.0 (sampling setup follows the SE Nature paper; official script `NUM_GENERATIONS=10, TEMPERATURE=1.0, MINP=0.0, SEED=10`).
- Scored object: question-level (the n samples of q jointly give one entropy); the output has no probabilistic meaning, with a range that depends on f and τ (bounded when ROUGE-L∈[0,1] and τ=1). Complexity is O(n²) similarity computations (the paper says KLE is O(N³), while SNNE needs no eigendecomposition).

## 2. Dataset settings (§5.1, App. B)
- QA (5 sets, following SE Nature): SQuAD, TriviaQA, Natural Questions, SVAMP (simple math word problems), BioASQ (Task B BioASQ11, 2023); no context (following the SE setting). Questions per set / splits: not reported in the paper (the official SE code defaults to 400 test questions, not confirmed in the SNNE paper → marked "not reported"). Correctness: for one low-temperature response at T=0.1, SQuAD F1 > 50% counts as correct (uniform across all QA datasets, App. B "Correctness measures"); 5-shot ICL, instruction "Answer the following question as briefly as possible."
- Text summarization (TS): XSUM, AESLC; machine translation (MT): WMT-14 de-en, fr-en (following LM-Polygraph); 0-shot; correctness measured by ROUGE-L / BERTScore (continuous scores, evaluated with PRR). 9 datasets in total.

## 3. Experimental protocol
- No training. For each question, 1 low-temperature (T=0.1) response is used to determine correctness, and another 10 are sampled to estimate uncertainty (App. B "Generation setting"; the original PDF writes "high temperature (T = 10)", which contradicts the main text "temperature 1.0 and 10 generated answers, directly adopted from SE" and the official script's TEMPERATURE=1.0; it should be a typesetting typo for T=1.0, and 1.0 is used following the code).
- Metrics: QA uses AUROC and AUARC (Nadeem 2009, following Lin et al. 2024); TS/MT uses PRR (Malinin 2017, following LM-Polygraph).
- Baselines: white-box KLE_full, SE, NE, EigenScore (INSIDE), SAR; black-box KLE_heat, DSE, pTrue, NumSet, LexSim, SumEigv, Deg, Eccen (graph methods of Lin et al. 2024), LUQ-Pair.
- Statistics: each experiment is run 3 times ("We conduct each experiment three times", A6000 GPU); tables report the mean, with ± std in some tables. Compute cost: not reported beyond the above.
- Ablations: Fig.4 (SQuAD, Llama-3.1-8B): number of generations 5/10/20, temperature 0.5/1.0/2.0 - more generations improve performance, saturating after 10; both T=0.5 and 2.0 degrade; τ∈{0.1,1,10,100} (Table 6, AUROC differences about ≤0.005).

## 4. LLM backbone settings
- Llama-3.1-8B (base name Llama-3.1-8B, the official script uses Meta-Llama-3.1-8B-Instruct), Phi-3-mini-4k-instruct (main text), appendix: Llama2-7B, Llama2-13B, gemma-2-2b-it, Mistral-Nemo-Instruct-2407. All are non-reasoning models with short answers; precision/context not reported; HF transformers.

## 5. Main results and conclusions (brief, key numbers)
- Average AUROC over the 5 QA datasets (Table 2, appendix): Llama-3.1-8B (accuracy 50.76): SNNE 0.83 vs DSE 0.79, NumSet 0.79, LexSim 0.79, Deg 0.79, Eccen 0.80, KLE_heat 0.78, pTrue 0.72; WSNNE 0.83 vs SE 0.79, NE 0.79, KLE_full 0.80. Phi-3-mini (42.84): SNNE 0.84 vs DSE 0.80, KLE_heat 0.77, pTrue 0.56; WSNNE 0.84 vs SE 0.80, KLE_full 0.81, NE 0.74. For the other 4 models SNNE/WSNNE lead by about 0.00–0.02 (e.g. Llama2-7B: WSNNE 0.81 vs SE 0.79, SNNE 0.80 vs DSE 0.79; Mistral-Nemo: WSNNE 0.82/SNNE 0.81 vs SE/DSE 0.79).
- AUARC (Table 3): Llama-3.1-8B: SNNE 0.74, WSNNE 0.74 vs SE 0.71, DSE 0.71, KLE_full 0.73; for some models (Llama2-7B/13B, gemma-2-2b, Mistral-Nemo) KLE_full ties with or is slightly above WSNNE.
- TS/MT (Phi-3-mini, PRR, Table 4): summarization (ROUGE-L as correctness) SNNE 0.27 vs DSE 0.20/NumSet 0.24; translation SNNE 0.63 vs DSE 0.58; LexSim is second among black-box methods on long outputs (ROUGE-L as f is best, Table 5).
- Authors' views: KLE_heat is actually worse than DSE (Fig.2, §5.2); SNNE outperforms SAR (previously SOTA on LM-Polygraph). The gaps are generally small (+0.01–0.04 AUROC in most QA settings).
- Authors' limitations (§7): multi-sentence/paragraph generation not studied; "for different data formats such as mathematical expressions, LaTeX equations, or code, our method requires further considerations. Designing an appropriate similarity function could help generalize our approach to these types of data."; requires multiple samples.

## 6. Fit to this project's unified benchmark
- Applicability: the method is general, relying only on the pairwise similarity matrix f(a_i,a_j), with no clustering required. But the paper is validated with ROUGE-L only on short-response (average 4–5 words) QA/summarization/translation, and **math/long-CoT is not validated at all**; the authors themselves admit that a similarity function must be designed for math. Applying ROUGE-L directly to CoTs of thousands of tokens is not the paper's setting (ROUGE-L is expensive on very long text, and word overlap between reasoning paths has no semantic meaning).
- Adaptation options: (1) **f = 0/1 final-answer equivalence** (math_verify; SNNE ≈ −mean_i log Σ_j exp(1[ans_i ≡ ans_j]/τ), which at τ=1 is determined by the cluster sizes n_k: −(1/n)Σ_k n_k log(n_k(e−1)+n)... i.e. merely a monotone function of cluster sizes; by Thm 4.1 it is in the DSE equivalence class, with almost the same information content as discrete SE / EigV / Deg); (2) f = ROUGE-L/character similarity or numeric similarity of the final-answer strings, which gives continuity but is not the paper's intent; (3) f = embedding cosine of the "extracted final answers" (an extension of the paper's embed variant). The suggestion is option (1) as the faithful degenerate version and option (3) as the SNNE adaptation with continuous similarity, clearly labeled.
- Extra cost per question: n−1 full long-CoT samples (the paper uses n=10); the similarity matrix takes n² cheap operations (answer level). WSNNE needs the mean token logprob of each sampled sequence (vLLM can return the logprob of sampled tokens; on long CoT, exp(mean logprob) varies little, the weights are ≈ uniform, and WSNNE≈SNNE, which needs attention).
- Pitfalls: (1) the temperature written as T=10 in the paper PDF is a typo; the actual value is 1.0; (2) τ=1 is the default, and when the ROUGE-L similarity lies within [0,1], exp(f) at τ=1 has limited discriminative power (small dynamic range of similarity); the code scans τ∈{0.1,1,10,100} in compute_snne, so it must be fixed (τ=1 recommended, consistent with the paper's default); (3) the default includes the self-similarity term selfsim=True; (4) in QA the question is concatenated before the answer before computing similarity (`CONCAT=True`), which must be changed to compare answers only for long questions such as math; (5) the sampling setup T=1.0 (no top-p/top-k stated, MINP=0.0) differs from the recommended Qwen3 thinking sampling (T=0.6), so it must be unified and recorded; (6) it is a question-level score, so the evaluated response must be fixed for evaluation.
- Recommended faithful implementation: n=10, T=1.0, τ=1, SNNE (black-box) + WSNNE (with logprob weights); f first uses 0/1 answer equivalence (equivalent to DSE), with a continuous-similarity variant based on answer embeddings given in the appendix.

## Implementation: mean inside the logarithm
The log Σ_j in the SNNE score sums over the K responses, which shifts it by log K between the K=4 training pool and the K=8 test questions. As a result, the Platt mapping fitted on the training pool saturates on the test set, the probability stays near 1, and Brier equals 1 − accuracy. The mean is now taken inside the logarithm (i.e. log K is subtracted): AUROC is unchanged for fixed K, and the calibration mapping can be used across K.
